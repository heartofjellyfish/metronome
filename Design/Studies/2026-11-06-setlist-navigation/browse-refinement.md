# Browse refinement — proposal

User approved edit and new-list layouts. Freeze those. Only refine browsing.

- Remove Start from first song rather than rename a play action as navigation. Every song row enters Live View in the browsed setlist context. No auto-advance or song-duration behavior.
- One combined back key “‹ 全部歌单”; close opposite. Name owns a full-width line.
- Small “3 首歌曲” belongs inside the shared list well as its header, not between name and actions.
- Edit setlist is one quiet full-width cream hardware key anchored at bottom. Keep it outside the scrolling song content and above safe area, with enough scroll padding that the last song cannot be obscured.
- This makes room for more song rows, at the cost of a little intentional body whitespace for short lists. Recessed list still hugs content; do not draw an empty well to fill the screen.
- Stopped: select song, enter Live View, remain stopped; user presses Play there. Playing: deliberately selecting a song applies it and stays playing. Back and close never restart or stop the clock. Merely browsing a list does not select it as the active setlist.
- Repeated use: back from Live View restores list scroll and context. Choose another song, or reorder via left handle; ordinal updates and current song remains identified by ID. Next/previous in Live View uses this specific list, including when song exists in several lists.
- Empty list: “0 首歌曲” and minimal empty state; bottom Edit setlist is the sole route to adding songs, avoiding a second redundant button. One-song list does not display spurious next song.
- Footer edit enters the approved draft editor. Preserve cancel/save semantics and clarify deletion retains songs.

Not implemented. Image Gen screenshot is an illustrative proposal, not measured native output.
