# Metronome and Tuner 首发范围与并行计划

更新于 2026-11-22。首发以常用弦乐和中国民乐为重点。[页面标准](page-standards.md)是所有 session 的验收依据。[乐器目录规划](instrument-catalog-plan.md)是后续扩库和文化发现的储备。公开首发名单由发布验收决定。

## 首发给用户什么

乐手在排练或演出前打开同一个 App，能找到自己的乐器，调准再回节拍器。优先保证整套流程可信、够快、可以重复。在现有 App 记录和 bundle ID 上更新，拟用 **Metronome and Tuner** 作为商店名称。19 个字符在 Apple 的上限内，提交前由发布负责人检查各市场名称可用性，协调本地化商店名、系统显示名、说明、截图和审核备注。产品沿用免费、无广告。 [产品约定](../../AppStore/product-marketing.md) · [Apple 名称规则](https://developer.apple.com/help/app-store-connect/reference/app-information/app-and-compliance-information)

| 首发层级 | 乐器和功能 | 放行门槛 |
| --- | --- | --- |
| 必须 | Chromatic 通用调音，吉他（6、7、12 弦），电贝斯（4、5、6 弦），普通／男中音尤克里里，小提琴、中提琴、大提琴、低音提琴，五弦班卓、曼陀林 | 现有 14 个常用弦乐配置逐个配对真实弦序、预设与定位。实际验证至少覆盖四种结构（独弦、成对弦、低音弦、弓弦），以及泛音、邻弦、尾音和重新跑音。特别查 7 弦低 B、贝斯低音、12 弦和曼陀林的同音／成对弦。 |
| 首发中国民乐候选 | 主线已有二胡、琵琶、古筝、古琴和 410 型扬琴。扩库分支已实现中阮、大阮、小阮、高音阮、低音阮，以及马头琴、冬不拉、柳琴、大三弦、高胡和中胡。共 16 个调弦配置。 | 逐项检查默认空弦、弦号、弦轴或弦组映射与完成反馈。实琴回归覆盖低音阮、两弦拉奏和多弦分组等代表结构。按验收结果纳入首发。待验证的专页可通过 Chromatic 或自定义调音满足基础需求。扩库分支的 `next-catalog-audit.md` 记录配置和实物依据。 |

| 可调打击乐 | 定音鼓、卡林巴 | 前者按实际鼓径和目标音，后者按真实音片和音阶。用手头实物验证再纳入首发宣传；演示音不能代替调音流程。 |
| 后续版本 | 文化入口重组、地区新乐器、大规模管乐长音校音、钢琴和手碟等音高检查 | 保留代码与既有配置的兼容。笛子有调接头和合奏校音需求，归后续共享校音。首发宣传以内测已验证的实际能力为准。 |

## 里程碑

| 阶段 | 交付与退出条件 | 用户收益 |
| --- | --- | --- |
| M0 · 冻结范围 | 基线推到 GitHub main。发布负责人与体验负责人共同核对常用弦乐和 16 个中国民乐候选，记录已通过验收与暂缓的配置。准备 TestFlight 候选，后续新增乐器继续各自迭代。 | 常用琴和中国民乐都能从明确的入口找到。 |
| M1 · 真实调音验收 | 在 iPhone 上按「打开 → 选琴 → 定弦 → 连调两三根 → 切回节拍器 → 重开」验证。检查调准、不误亮、权限拒绝和重新授权、耳机与扬声器路由、无输入和切换。测冷启动到首屏，小屏读数和触区。核对旧版更新后保留节拍器预设、歌曲和设置。GitHub 基线上的模拟器历史失败要单独列出，正式候选核对相关功能在真机是否正常。 | 用手机即开即调，不会因假绿、断音或丢定弦而中断排练。 |
| M2 · TestFlight 到 App Store | 准备真实截图（节拍器、吉他／提琴、一个已验收的地域乐器）、本地化名称和审核说明，核对麦克风用途说明与实际行为。验证商店构建再用现有 App 记录提交。若选分阶段发布，说明它只限制自动更新，手动下载仍可获得。 | 现有用户平滑升级，商店清楚说明两个模式。 [Apple 分阶段更新](https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases/) |
| M3 · 扩库和发现 | 从首批已验证传统开始增加文化入口。优先做已经有人要找、演奏前有明确调音步骤、可取得实物和录音的乐器。把搜索失败、音名混淆、弃用原因和老师反馈作为下一批依据。 | 更多乐手能按传统或本地名称找到自己的乐器。 |

## 三个并行 session

每个 session 从同一个 GitHub main 基线开工作树。发布负责人决定候选冻结点与发布合并顺序。

| Session | 负责 | 边界与交接 |
| --- | --- | --- |
| 发布 | 首发名单和可见性、升级与真机回归、版本号、App Store 名称与素材、TestFlight／审核／发行。 | 维护唯一发布清单，首先合并阻断项，集中在发布分支核对持久化与跨模式音频。统一安装候选并记录测试证据。 |
| 扩展乐器库 | 文化目录、别名、预设、每种新乐器的实物参考与录音验证。先做研究和可独立评审的配置。 | 按后续版本排序，新增配置先留在自己的工作树。冻结后进入首发的例外由发布负责人明确。 |
| 精调页面 | 打磨首发乐器的线稿、弦轴映射、字号、比例、分组、测音状态和连续操作。用真实演奏流程优先修有阻断的问题。 | 先完成首发名单，单独提交页面或交互回归。变更共用表盘、选择器或持久化时，和发布及扩库负责人同步测试范围。 |
