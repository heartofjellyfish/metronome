# 调音器页面标准

更新于 2026-11-22。沿用 [App 的品牌和界面规则](../../AppStore/brand-preferences.md)。改调音器时以这里的验收标准和当前代码为准。乐器取舍、文化入口和待验证候选见 [乐器目录规划](instrument-catalog-plan.md)。

## 一个页面只解决一个调音任务

- 打开就清楚现在在调什么、偏高还是偏低、哪根或哪组已经调准。音名和表盘是第一层，当前弦号是第二层，轮廓和控制服务于定位。音名和八度作为一组读数，弦号另留间距，位置在切换状态时保持稳定。
- 用现有象牙白、暖灰、石墨线和绿色完成标记。线宽表达结构与弦粗细，调准反馈也用勾等非颜色线索。读数要能扫一眼看懂。优先修比例、光学居中、留白、对比度和命中区，避免用额外色块、徽标、重复文案弥补层级。
- 乐器入口在顶栏，定弦是独立入口。默认画面尽量只露出当前场景的高频操作。A4、响应、确认反馈、谱音／实音优先等放设置。每种乐器记住自己的定弦，换琴或重开按记忆设置恢复。显示名称、分类、图标和调弦预设的变更不能破坏已保存 ID。
- 乐器调音表盘使用现有短针。指针穿过中心到两侧时，其外露长度一致，尾部用浅切边自然收住。检测应稳定，颜色和方向的含义一致。保留实际音高变动所需的灵敏度，区分初拨、尾音、泛音、短时噪声和真正的重新跑音。
- Chromatic 保留简洁圆盘。用扇区表达音高偏差，稳定地贴近目标后才逐步增强绿色反馈。目标音和持续音放在同一个控件。不同音频路由下核对播放和恢复监听，当前暂停拾音的参考音流程应如实显示。听声能判断音高，遇同音的不同物理弦时由用户确认。

## 让乐器图能用来找弦

- 先对照确定型号、演奏者视角、弦序、绕线和遮挡。取最能帮助定位的一段，吉他、贝斯、提琴、琵琶优先琴头，古筝、古琴等需要看到更多弦路时再展示琴身。不要把照片的透视、光影或装饰纹样带进功能线稿。
- 调音页采用可交互的原生矢量线稿。结构按部件绘制，弦、接触点、桥、弦轴和旋钮的连接要清楚。孔内、盖板下或藏在木边后的弦段按实物遮挡。调准时整条对应链路和勾一起变绿，换弦保留已完成的标记。全弦完成后才点亮乐器轮廓。真实的重新拨弦且偏差稳定时只撤销跑音的弦与全绿状态。
- 琴头、琴钮和点按区域真实对应。弦号、音名和八度能在小屏看清。比如 12 弦吉他和曼陀林要逐根或逐组明确区分，文案以实际上能确认的粒度为准。相同音高的两根弦要能分别选中。乐器选择器里的小图标用单色中空轮廓，保留弦数、琴钮布局和最易认出的特征。
- 分组和总览解决不同尺度的定位。分组图要按真实远近、弦序、音高和部件关系裁近，总览以全貌和全弦序为重。切换时表盘、读数轴和底部标签栏保持位置。优先用一致的点按面积，线条压缩时避免把相邻弦的点按区域混在一起。
- 校音、伴奏参考音和调弦是不同任务。移调乐器同时显示谱音和实音，设置控制大小的优先级，接收和参考音使用实音。持续音、定目标音和长音反馈复用现有组件。逐音证明其工作流之前，不给只做音高检查的乐器画可调旋钮或宣称支持完整调音。

## 当前示范页

| 页面 | 必须保住的特征 |
| --- | --- |
| 吉他与贝斯 | 正面琴头，参考实际型号。单侧、两侧、无头琴用真实结构与通用排列名区分。同一根线到对应的钮，定弦与琴头布局是两个选择。 |
| 提琴、低音提琴 | 同一家族的石墨线稿，保留弦轴箱的体量和卷头。弦轴与内杆一体，绕线贴轴，按实物遮挡。低音提琴保留齿轮机构。 |
| 班卓、曼陀林 | 班卓保留侧面第五弦钮和清晰的短弦路径。曼陀林成对分组，括线贴近相应弦组，和琴形之间留间隔。 |
| 琵琶、二胡 | 琵琶轴位错列，最下面轴按正面实物遮挡，按实物标弦枕和品。二胡琴轴与杆不能断开，弦与轴一一对应。 |
| 古筝 | Far／Middle／Near／All 顺序固定，远侧为第 21 弦起、近侧为第 1 弦。三组共用线宽曲线，近侧画实际琴码，另外两组按裁切处理。开盖右端画出扳手空间，弦进孔后藏在岳山后，轴上画可见绕线。分组线稿两侧留白，最外弦到外沿有空间。All 的对称浅弧琴尾和 21 根弦比音名表更显眼，点接弦和右侧盖板保留，轴只在分组出现。 |
| 扬琴、Sitar、Koto | 根据实物弦组、桥位或主弦／共鸣弦组织，沿用各自真实定弦。总览与分组应能回到同一根或同一弦组。Koto 的同音弦保留独立物理编号。 |
| 管乐、打击乐、人声 | 清楚表达要测哪一个音、能否真正调节、是否只是定目标练习。可调定音鼓按实际鼓径给音域。吹管头部结构和移调量以具体型号核实。 |

## 验收和并行工作

- 每个乐器任务先写一句可复现的场景：“谁在什么情况下，调哪个机械部件，听哪个音，怎么知道完成”。随后检查功能正确性、演奏方式和术语、图形真实性、点按效率、读数稳定性和可读性。用现场动作来判断哪一项仍需修正。
- 同一台模拟器对照首屏、选中、偏低、偏高、调准、换下一根和重拨跑音。至少看第二、第三个连续操作。设置或定弦比较需要反复点选时让选单保持打开。核对静止、参考音或节拍器播放期间，再关闭和重开。
- 原生入口和部件见 [TunerView](../../TheMetronome/TunerView.swift)、[琴头](../../TheMetronome/TunerHeadstock.swift)、[地区乐器的交互线稿](../../TheMetronome/TunerRegionalHeadstock.swift)、[古筝线稿](../../TheMetronome/TunerGuzhengArtwork.swift)、[选择器](../../TheMetronome/TunerLibrary.swift)。音高和状态用 [TunerTests](../../TheMetronomeTests/TunerTests.swift)，连续点按和截图用 [TunerUITests](../../TheMetronomeUITests/TunerUITests.swift)。说明证据是合成音、注入录音、模拟器操作还是真机实琴。
- 并行 session 从 GitHub `origin/main` 开各自分支和工作树。按一类任务拆分，例如文化索引、单一乐器家族、拾音稳定性。文化索引负责人汇总目录、别名和翻译冲突。各乐器以独立资产和 Swift 文件交付。如果必须改共用目录、翻译或页面，把共享差异集中在小提交里。发布前再取最新 main 整合和验证。手机安装串行进行，交接时写清版本、已验证状态和未验实琴项。
